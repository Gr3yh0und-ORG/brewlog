# Review brewlog / frontend (2026-10-28)
Reviewed commit: 09a543e. Files read: CLAUDE.md (first 80 lines), README.md (first 80 lines), web/index.html, web/i18n/en.json, web/i18n/de.json. Tests: not run — no frontend tests exist in the repo (tests/ covers export, labels, rollback only; none of them execute index.html or the i18n files).

## Summary
1. `web/index.html:1` has a corrupted doctype (`<!DOdeplht iCTYPE html>`), putting the whole site into quirks mode.
2. `web/i18n/en.json` is mojibake-corrupted: every non-ASCII character was replaced by literal `?` bytes (`"back": "??????? Back"`), so the English UI shows garbage.
3. `noteHTML()` (web/index.html:708) "sanitizes" DB-sourced HTML with regexes that are trivially bypassable (unquoted event handlers), and `renderGallery` interpolates filenames into a single-quoted attribute unescaped — XSS via crafted export data.

## Bugs

- **[HIGH] web/index.html:1 — corrupted doctype.**
  `<!DOdeplht iCTYPE html>` (verified with `od -c`: bytes `< ! D O d e p l h t   i C T Y P E   h t m l >`).
  The browser cannot parse this doctype, so the page renders in **quirks mode**: box-model, `position: sticky` (used by `.app-header` and `.detail-header`) and grid/flex sizing behave differently across browsers.
  Fix: replace line 1 with `<!DOCTYPE html>`.

- **[HIGH] web/i18n/en.json:4-6,31-34,86 — non-ASCII characters destroyed (literal `?`).**
  `"back": "??????? Back",` / `"loading": "Loading???????",` / `"stats_sha": "???? Brewhouse Eff.",` / `"dl_svg": "Label 1?????",`.
  Verified with `od -c`: the file contains raw `?` bytes, not UTF-8. The `←`, `…` and `Ø` characters were lost (likely a save through a codepage-1252 pipe). The English UI renders "??????? Back". The German file (de.json:4 `"back": "← Zurück"`) is intact, so only en.json needs repair: restore `← Back`, `Loading…`, `Loading recipe…`, `Ø Sudhausausbeute` etc. (the de.json originals show what each string should contain).

- **[HIGH] web/index.html:708-723 — `noteHTML()` HTML branch is a bypassable sanitizer.**
  ```js
  .replace(/\s+on\w+="[^"]*"/gi, '')
  .replace(/\s+on\w+='[^']*'/gi, '')
  .replace(/href\s*=\s*["']javascript:[^"']*["']/gi, '');
  ```
  Notes are taken from the KBH2 database and injected unescaped (`<div class="note-text">${noteHTML(notes[k])}</div>` at line 1781, inside `renderNotes` at line 1768). The regexes only strip **quoted** `on*` attributes and only `javascript:` in `href`. Verified by reading: `<img src=x onerror=alert(1)>` (unquoted attribute) and `<iframe src=...>` survive untouched — any recipe note containing them executes on page load. Risk depends on who can edit the database, but it is a real XSS sink.
  Fix: don't hand-roll sanitizing — either always run `esc(s)` and only support plain text, or pass through a real sanitizer (e.g. DOMPurify, or a whitelist rebuild via `DOMParser` + allowed tag/attribute list).

- **[MEDIUM] web/index.html:1764 — unescaped JSON inside single-quoted attribute.**
  `<div class="gallery" id="gallery-imgs" data-images='${JSON.stringify(images)}'>`
  `images` comes from the exported data. A filename containing `'` (legal on ext4; only `esc()`-ed values elsewhere are safe) terminates the attribute and injects arbitrary markup/attributes. Fix: `data-images="${esc(JSON.stringify(images))}"` and read it back with `JSON.parse(el.dataset.images)` (dataset already returns the decoded value).

- **[MEDIUM] web/index.html:661-663 — `getStatus` fallback can never fire.**
  `return { label: t('status_' + n) || t('status_3'), ... }`
  `t(key)` (line 860: `return (window.T && window.T[key]) || key;`) returns the **key itself** when the key is missing — a truthy string. So an unexpected status (e.g. 4 shown correctly, but any unknown value like 5) renders the literal string `status_5` to the user instead of falling back to "Finished". Fix: `const lbl = window.T['status_' + n] || window.T.status_3 || t('status_3');` or make `t()` return `null`/`''` on miss.

- **[MEDIUM] web/index.html:891-903 — `setLang()` has no error path; a bad language file is persisted.**
  ```js
  localStorage.setItem('lang', code);
  ...
  fetch(`i18n/${code}.json`).then(r => r.json()).then(lang => {...});
  ```
  No `.catch` and no `r.ok` check (unlike the index fetch at line 924). If a translation file is missing or malformed (e.g. 404 returns HTML), `r.json()` rejects into an unhandled rejection, the UI silently stays in the old language, but the broken code is already saved to `localStorage` — so every later visit starts in the broken language too (line 856). Fix: add `.catch(() => { /* revert currentLang + localStorage to previous */ })` and check `r.ok`.

- **[MEDIUM] web/index.html:923-940 — error box shows raw i18n keys when `index.json` is missing.**
  `Promise.all` (line 923) rejects as soon as `data/index.json` 404s (line 924 throws on `!r.ok`), so `window.T = lang` (line 927) never runs. The catch handler at lines 932-940 then renders `${t('error_no_data')}` → the user sees the literal `error_no_data` / `error_no_data_hint` instead of "Data not found". Fix: apply the already-fetched `lang` to `window.T` inside the second fetch's `.then` (it has `.catch(() => ({}))` so it always resolves), or fetch i18n separately before the `Promise.all`.

- **[MEDIUM] web/index.html:1087 — year grouping is timezone-shifted for date-only strings.**
  `const key = b.braudatum ? String(new Date(b.braudatum).getFullYear()) : RECIPE_KEY;`
  A `"YYYY-MM-DD"` string is parsed as UTC midnight, but `getFullYear()` uses local time. In UTC-negative timezones (all of the Americas) a brew dated `2027-01-01` is grouped under **2026**. `fmtDate` (line 697-700) has the same `new Date(dt)` pattern and shifts the displayed day back by one there. Fix: parse manually (`b.braudatum.slice(0,4)` for the year; split the string for `fmtDate`) instead of `new Date()`.

- **[MEDIUM] web/index.html:785-797 — a non-numeric taste rating breaks the radar chart with `NaN`.**
  `(tastes || []).forEach(t => { tm[t.notes] = parseFloat(t.rating); });` … `tm['Bitterkeit'] ?? 0.5,`
  `parseFloat("gut")` → `NaN`; `??` only guards `null`/`undefined`, so `NaN` flows into `catmullRomPath` and emits `C NaN NaN, ...` — the whole SVG path is dropped by the browser and the radar disappears (card thumb and detail). Fix: `const v = parseFloat(t.rating); if (!isNaN(v)) tm[t.notes] = Math.min(1, Math.max(0, v));`

- **[LOW] web/index.html:727-729 — `stars()` cannot render a 0-star or >5-star rating.**
  `if (!n) return '–';` treats a legitimate rating of `0` as "no rating", and `n = 6` renders six `★` with no `☆`. Fix: `if (n == null) return '–';` and clamp `const r = Math.min(5, Math.max(0, Math.round(n)));`.

- **[LOW] web/index.html:1165-1169 + 1182 — Escape/history pollution.**
  `closeDetail()` runs `history.pushState(null, '', location.pathname)` unconditionally, and the Escape handler at line 1182 calls it even when the detail overlay is closed. Pressing Escape on the list page pushes a new history entry every time; pressing Escape twice pushes two entries the user must back out of. Fix: early-return from `closeDetail()` when `!detail.classList.contains('open')`, and only call `pushState` in that case. Also: with the lightbox open, one Escape closes both the lightbox (line 1846) **and** the detail behind it (line 1182 fires regardless) — check `lightbox.classList.contains('open')` in the line-1182 handler and return.

- **[LOW] web/index.html:1143-1156 — `file` / `sudnummer` interpolated into fetch URLs without encoding.**
  `fetch(\`data/${file}\`)` and `fetch(\`data/${sudnummer}_influxdb.json\`)`. A crafted `index.json` (e.g. `file: "../../etc/passwd\0"` or a URL-encoded traversal) controls the request path. On a static host the blast radius is limited to same-origin GETs, but it is still unvalidated path traversal. Fix: validate before fetching, e.g. `/^[\w.-]+\.json$/.test(file)`, and `encodeURIComponent(String(sudnummer))`.

## Implementation gaps

- **[MEDIUM] web/index.html:979-985 — status "Discarded" (4) has no filter button.**
  `statusFilters` lists only keys `0`–`3`, although `STATUS_CLS` (line 660) defines `st-4`, `status_4` exists in both i18n files (en.json:19), and discarded beers appear in the "All" view and in the KPI `brewed` count. A user cannot filter to (or exclude awareness of) discarded brews. Fix: add `{key:'4', label: t('status_4'), count: byStatus[4]||0}` — the existing `count === 0` guard (line 989) already hides it when unused. Related: line 1032 `const brewed = allBeers.filter(b => b.status >= 1);` counts Discarded brews into "Brews" / "Total brewed" / "avg SHA" KPIs; decide whether `b.status >= 1 && b.status !== 4` is intended.

- **[LOW] web/index.html:975 vs 1045 — dead code: `headerKpis` is written twice per `init()`.**
  Line 975 sets `headerKpis.innerHTML = '<div class="kpi-export">…'` and line 1045 (same `init()` call, a few lines later) overwrites it with the full KPI block. The first assignment can never be seen. Fix: delete lines 975-976.

- **[LOW] web/index.html:950-956 — `fmtDays()` hardcodes German unit abbreviations.**
  `` return `${n} T`; `` / `W` / `Mo` / `J`. The README promises "Multilingual — 8 languages", but an English user sees "12 Mo" for a 360-day conditioning time. No i18n keys exist for these units. Fix: add `unit_days/unit_weeks/unit_months/unit_years` keys and use `t()`.

- **[LOW] web/index.html:697-700 — `fmtDate()` always uses the `de-DE` locale.**
  `d.toLocaleDateString('de-DE', …)` ignores `currentLang`; EN users get `31.12.2025`. Cosmetic for DD.MM.YYYY, but it should follow `currentLang` like everything else. Fix: `toLocaleDateString(currentLang, …)`.

- **[LOW] web/index.html:2 — `<html lang="de">` never changes.**
  `setLang()` updates the flag and all labels but never sets `document.documentElement.lang`, so screen readers and translators keep assuming German after switching to English. Fix: add `document.documentElement.lang = code;` in `setLang()`.

- **[LOW] web/i18n/en.json / de.json — keys defined but never used.**
  Verified by diffing `t('…')` call sites against the JSON: `stats_abv`, `stats_sw`, `stats_ibu`, `stats_since`, `hero_brew_no`, `col_form` are in both files but no code path requests them (the `note_*`/`rating_*` keys are built dynamically and *are* used; these six are not). Dead translations drift out of date silently. Fix: delete them, or wire them up (an avg-ABV KPI would make `stats_abv` earn its place).

- **[LOW] web/index.html:891-903 — open detail overlay keeps the old language after `setLang()`.**
  `setLang` re-runs `init(cachedIndex)` (grid only). If the detail overlay is open, all its section titles stay in the previous language until it is reopened. Fix: remember the last `(bj, pd)` and re-call `renderDetail` in the `setLang` `.then` when `detail.classList.contains('open')`.

## Improvement suggestions

1. Move the pure helpers (`esc`, `fmtDate`, `fmt1/0`, `daysBetween`, `fmtDays`, `radarVals`, `noteHTML`, `getStatus`) into `web/app.js` (still no build step, still one `<script src>`). This makes findings 1-6 testable without DOM and shrinks index.html.
2. Replace the `Promise.all` bootstrap (line 923) with independent loads: render the grid as soon as `index.json` arrives, and re-render on translation arrival — currently a slow i18n fetch delays the whole first paint, and an i18n failure suppresses correct error-box text.
3. Cache-bust language files: `fetch(\`i18n/${code}.json?v=${encodeURIComponent(index.exportiert || '')}\`)` — after an FTP deploy, stale `en.json` in the browser cache silently mixes old and new strings.
4. `renderCharts()` (line 1423; `if (!malts.length) return '';` at line 1426) returns `''` when there is no malt even if hops have IBU values; render the hop donut independently of the malt one.
5. `init()` rewrites both filter bars and the whole grid on every language switch; acceptable at home-brewery scale, but the click handlers (line 989 style/status buttons, line 1106 `c.onclick = ...` on cards) are re-created on every render — a single delegated listener on `#filterBar`/`#styleBar`/`#grid` would remove that churn.
6. `SENSOR_COLORS`/`FERM_COLORS` overflow silently past 3/4 series (`colors[i] || colors[0]` reuses the first color). At minimum cycle with `colors[i % colors.length]` so the 4th brew-day sensor is distinguishable from the 1st.
