# Review brewlog / python (2026-10-28)
Reviewed commit: 09a543e. Files read: web/export.py, web/utils.py, web/fetch_influxdb.py, web/generate_labels.py, tests/helpers.py, tests/test_export.py, tests/test_labels.py (plus first 80 lines of CLAUDE.md/README.md, ci.yml, requirements.txt for conventions). Tests: the given command `python -m pytest -q tests/test_export.py tests/test_labels.py` fails at collection (2 errors, `ModuleNotFoundError: No module named 'helpers'`) because `tests/__init__.py` makes `tests` a package and there is no conftest.py to set sys.path. With `PYTHONPATH=tests` the same command gives **18 passed, 0 failed**. CI (`python3 -m unittest discover -s tests`, the command `.github/workflows/ci.yml` actually runs) also passes.

## Summary
1. The documented pytest invocation cannot collect the suite at all (tests/__init__.py + no conftest); only CI's unittest-discover path works, so any contributor or tooling using pytest gets a hard import error.
2. Unvalidated data can crash the tools: a malformed `label_color` in enrichment JSON raises ValueError inside `hex_to_rgb` (generate_labels.py), and `_parse_dt` (fetch_influxdb.py:94) has an unwrapped fallback that re-raises ValueError, killing the whole fetch run for one bad date string.
3. Multiple promised behaviors are missing: CLAUDE.md's `/deploy` points to `infrastructure/scripts/deploy.sh` which does not exist; requirements.txt promises Pillow "auto-resize oversized brew photos" which export.py never does; and stale `{n}_beerjson.json`/`.xml`/`_influxdb.json` files for deleted brews are never cleaned from `web/data/`.

## Bugs

- **[HIGH] tests/test_export.py & tests/test_labels.py — suite is un-runnable with pytest.**
  `tests/__init__.py` exists and there is no `conftest.py`, so pytest imports the tests as package `tests.*`; `tests/test_export.py:7: import helpers` then fails with `ModuleNotFoundError`. Only `unittest discover` (which inserts the start dir on sys.path) works, so the documented/tested invocation silently diverges from CI. Fix: add `tests/conftest.py` containing `import sys, os; sys.path.insert(0, os.path.dirname(__file__))` (or delete `tests/__init__.py`).

- **[MEDIUM] web/generate_labels.py:230 — unvalidated `label_color` from external JSON crashes label generation.**
  `bg = sb.get('label_color') or '#D2CECE'` accepts any string from `input/enrichment/{n}.json`; line 233 `acc_col = accent_color(bg)` → `hex_to_rgb` (`int(h[i:i+2], 16)`) raises `ValueError` on e.g. `"red"` or `"#GGG"`, aborting every remaining label. Fix: validate with `re.fullmatch(r'#([0-9a-fA-F]{3}|[0-9a-fA-F]{6})', bg)` and fall back to `'#D2CECE'` otherwise.

- **[MEDIUM] web/fetch_influxdb.py:99-101 — `_parse_dt` fallback re-raises and kills the whole run.**
  ```python
  except ValueError:
      dt = datetime.fromisoformat(s[:10])
  ```
  If the DB stores a non-ISO date (e.g. KBH2 German `01.04.2024`), both `fromisoformat` calls raise `ValueError`; the exception propagates through `fetch_brew` → `main`, so one bad brew aborts every other brew's fetch. Fix: wrap the fallback too and `return None`, then let `fetch_brew` skip that brew with a printed warning. (Whether KBH2 actually writes non-ISO dates is **unverified**, but the crash path on malformed input is real.)

- **[MEDIUM] web/generate_labels.py:426 — beer name interpolated into an XML comment unescaped.**
  `+ (f'<!-- {comment} -->\n' if comment else '')` is called with `f'{BREWERY_NAME} ... {recipe.get("name")}'` (line 455/465). A beer name containing `-->` or `--` produces malformed SVG (XML comments may not contain `--`); all other user strings go through `esc()` but this one does not. Fix: `comment.replace('--', '-')` or pass it through `esc()` before interpolation.

- **[MEDIUM] web/export.py:410-421 — missing sub-tables in the user DB crash export with a raw sqlite error.**
  `cur.execute(f"SELECT * FROM {table} WHERE SudID=? ORDER BY {order}", (sid,))` assumes `Tags`, `Hauptgaerverlauf`, `Bewertungen` etc. all exist; an older/partial KBH2 DB raises `sqlite3.OperationalError: no such table` with no useful message (the table-name f-string itself is safe — the names are hardcoded, no injection). Fix: check `sqlite_master` once and skip missing tables with a warning.

- **[LOW] web/export.py:489-506 — a NULL `Sudnummer` silently produces `None_beerjson.json`.**
  `snum = row['Sudnummer']` is never checked; `fname = f"{snum}_beerjson.json"` then writes/overwrites `None_beerjson.json` for every such row (and `load_enr(None)` reads `None.json`). Fix: skip the row (with a warning) when `snum is None`, or fall back to `row['ID']`.

- **[LOW] web/fetch_influxdb.py:233-234 — `stop_dt` can precede `start_dt`.**
  If `Abfuelldatum` is earlier than `Braudatum` (data-entry error), `min(_parse_dt(abfuelldatum)+2d, now)` yields a range with stop < start; the Flux query returns nothing or errors, and the failure is silent. Fix: `stop_dt = max(stop_dt, start_dt + timedelta(days=1))`.

- **[LOW] web/fetch_influxdb.py:283 and web/generate_labels.py:417 — CLI arg parsing is silently lossy and can crash.**
  `args = [a for a in sys.argv[1:] if a.isdigit()]` drops typos silently (`python generate_labels.py 3l` regenerates **all** labels — surprising and wasteful), and `str.isdigit()` accepts characters like `'²'` where `int(a)` then raises `ValueError`. Fix: validate with `try: int(a)` and error out on non-numeric args.

- **[LOW] web/utils.py:28-29 — `load_env` does not strip quotes or inline comments.**
  `env[k.strip()] = v.strip()` keeps the quotes of `FTP_PASS="p@ss"` and everything after `#` in `FTP_HOST=x  # comment`, producing silently wrong credentials/URLs. Fix: `v = v.strip().strip('"').strip("'")` (and split on `' #'` when unquoted). The rest of the README flow assumes `.env` is dotenv-compatible.

- **Security notes (assessed, acceptable / low):** no secrets are hardcoded — `INFLUXDB_TOKEN` etc. come from the env file (utils.py) and are never printed (fetch_influxdb.py:294-297 prints URL/bucket only). Flux queries interpolate only local `.env` values (fetch_influxdb.py:132-136), so quote-injection requires the operator to corrupt their own config — LOW, but a `"` in a topic name would break the query with a confusing error. All user-derived strings in SVG go through `esc()` except the XML comment (above). No subprocess/HTML/`eval` anywhere. No races (single-threaded local scripts).

## Implementation gaps

- **[HIGH] CLAUDE.md — release instructions point at a script that does not exist.** `Run /deploy (it calls infrastructure/scripts/deploy.sh)` — there is no `infrastructure/` directory at all; the script lives at `deploy/deploy.sh`. Anyone (or any agent) following CLAUDE.md literally will fail. Fix: correct the path.
- **[MEDIUM] requirements.txt vs web/export.py — promised photo resize is not implemented.** `requirements.txt` says `Pillow # export.py: auto-resize oversized brew photos before upload`, but export.py only reads EXIF (`_photo_sort_key`, line 448) and `shutil.copy2`s originals (line 475) — no resize/thumbnail anywhere (`grep -n "resize\|thumbnail" web/export.py` → nothing). Either implement resize or fix the comment; oversized originals hurt the static-host use case.
- **[MEDIUM] web/export.py:439 — no cleanup of stale exports.** `export()` creates `DATA_DIR` and writes per-brew files but never removes files for brews deleted from the DB; `{n}_beerjson.json`, `{n}_beerxml.xml`, `{n}_influxdb.json`, `web/images/*` and `web/labels/*` from deleted brews stay and keep getting deployed. Fix: before the loop, delete files matching those patterns whose `snum` is not in the current row set.
- **[LOW] Dead code:** `web/export.py:101 _sg_to_plato` is never used; `web/generate_labels.py:233 acc_col = accent_color(bg)` is computed and never rendered (and `accent_color` has no other caller) — the label color stripe uses `beer_hex` instead, so the configured `label_color` has no visible effect beyond a crash surface.
- **[LOW] Unhandled enrichment JSON errors.** `load_enr` (export.py:432-437) and `generate_label` (generate_labels.py:442) / `fetch_brew` (fetch_influxdb.py:216) `json.load` user files with no try/except — one malformed enrichment file aborts the whole export with a traceback. Wrap per-file and warn.
- No `TODO`/`FIXME` markers exist in the reviewed files (grep found none). No other README claims were contradicted within the files in scope.

## Improvement suggestions

1. Add `tests/conftest.py` (two lines) so `python -m pytest tests/` works as documented — smallest fix, removes the biggest contributor papercut.
2. Validate `label_color` with a hex regex in `generate_labels.py` and fall back to the default (fixes the crash bug and documents the contract).
3. Wrap `_parse_dt` fully and skip brews with unparseable dates in `fetch_influxdb.py` instead of aborting the batch.
4. In `export()`, prune stale `{n}_beerjson.json` / `_beerxml.xml` / `_influxdb.json` files for brews no longer in the DB before writing (one glob + unlink loop).
5. Escape/neutralize `--` in `svg_wrapper`'s comment (one `replace`).
6. `load_env`: strip surrounding quotes and trailing `#` comments; the README tells users to hand-edit `.env`, so dotenv conventions will appear.
7. Replace the private PIL API `im._getexif()` (export.py:454) with the public `im.getexif().get(36867)` — `_getexif` is deprecated on some Pillow builds and returns a raw dict.
8. In both `main()`s (fetch_influxdb.py:283, generate_labels.py:417), reject non-numeric CLI args with an error instead of silently falling back to "all brews".
